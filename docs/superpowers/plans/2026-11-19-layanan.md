# Layanan: Pengajuan SDM & Pengaduan Internet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Semua akun (termasuk tanpa peran) mengajukan SDM di `/layanan/sdm` dan memantau di `/layanan/sdm/saya`; Manajer menyetujui (→ Tugas dari Manajer atau entri Planner, satu saja), menolak, atau membatalkan; semua akun mengadukan kendala internet di `/layanan/internet`, staf unit & Direktur melihat rekap di `/layanan/internet/rekap`.

**Architecture:** Tabel baru di `packages/db/src/schema/service.ts`. Aturan murni di `apps/admin/lib/layanan/rules.ts`, validasi zod di `schema.ts`, query/mutasi di `queries.ts`/`mutations.ts`, dipanggil aksi server tipis di folder route. Tautan ke tindak lanjut: `service_request.planner_entry_id` (RESTRICT) untuk Planner, `manager_task.service_request_id` (RESTRICT) untuk tugas; susunan SDM dibaca lewat join; pembatalan lewat satu fungsi `cancelRequestTx` yang dipanggil `deleteEntry`, `deleteManagerTask`, dan tombol Batalkan.

**Tech Stack:** Next.js 16 (App Router, `params`/`searchParams` Promise), Drizzle + PostgreSQL, `@workspace/auth`, zod 4, date-fns, vitest, MinIO (`lib/storage.ts`), `@workspace/ui` (field, input, textarea, select, combobox, checkbox, radio-group, reui date-selector, reui time-picker, domain assignment-rows, domain media-upload / reui file-type, table, tabs, badge, chart, alert-dialog, empty, card).

**Spec:** `docs/superpowers/specs/2026-11-19-layanan-design.md`

## Global Constraints

- Semua perintah di WSL setelah `. ~/.nvm/nvm.sh`, dari root repo. Jangan pnpm dari Windows terhadap `\\wsl.localhost`.
- Baca panduan Next di `apps/admin/node_modules/next/dist/docs/` sebelum menulis halaman/aksi/route handler (AGENTS.md).
- Komponen hanya di `packages/ui`; `apps/admin` hanya halaman dan file perakitan `_*.tsx` di folder route. **Tidak ada komponen baru**; satu-satunya perubahan komponen: prop baru di `packages/ui/src/components/domain/assignment-rows.tsx`. Bila ternyata butuh komponen lain, berhenti dan ajukan ke pengguna (nama + sumber).
- Warna hanya token `globals.css`. Badge status: Diajukan `info-light`, Disetujui `success-light`, Ditolak `destructive-light`, Dibatalkan `secondary` (varian `@reui` Badge, sudah dicek ada).
- Sebelum Task 7: skill `frontend-design:frontend-design`. Setelah Task 9: `anthropic-skills:web-design-guidelines`, MCP reui `validate_usage` + `get_audit_checklist` untuk item reui yang dipakai.
- Izin (sudah ada di `packages/auth/src/permissions.ts`, jangan diubah): `layanan.ajukan` (semua akun), `layanan.setujui_sdm` (Manajer), `pengaduan.lihat` (staf unit + Direktur).
- Tanggal `yyyy-MM-dd` (`IsoDate` dari `lib/planner/types`); zona WIB untuk rekap.
- Validasi teks: nama kegiatan trim 2–120; WA dinormalisasi ke digit dengan `+` opsional di depan, 9–16 digit; baris SDM 1–20; catatan setuju ≤ 500 (opsional); alasan tolak & catatan batal trim 3–500 (wajib); ruangan trim 1–80; deskripsi ≤ 1000; `started_at` ≤ sekarang + 5 menit.
- Rundown: maks 10 MB; MIME `application/pdf`, `image/jpeg`, `image/png`, `image/webp`, `application/msword`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`; key `requests/<uuid>.<ext>`.
- Judul tugas hasil persetujuan: `` `${jenis} · ${namaKegiatan}` ``.
- Pesan: "Pengajuan sudah diputuskan", "Isi catatan pembatalan untuk pengaju", "Pengajuan tidak ditemukan", pesan terima kasih pengaduan persis dari spesifikasi §8.2: *"Terima kasih, pengaduan Anda sudah kami terima dan akan menjadi bahan evaluasi layanan internet sekolah."*
- Label jenis kendala a–f persis spesifikasi §8.2.
- Galat aksi lewat `guarded()`/`UserError` (`lib/setting-crud.ts`). Id tidak dikenal atau bukan milik → `notFound()` (jangan bocorkan keberadaan).
- Setiap aksi git mengikuti bagian "Versioning" CLAUDE.md. Kerja di branch `feat/layanan` dari `main`. Tidak ada push tanpa persetujuan pengguna.

## Review Focus

1. Dua Manajer (atau dua tab) menyetujui pengajuan yang sama bersamaan, satu lewat tugas dan satu lewat Planner: hanya satu tindak lanjut tercipta, yang lain dapat "Pengajuan sudah diputuskan" dan tidak meninggalkan entri/tugas. → tes di Task 3 dan Task 4.
2. Dua tugas tertaut terakhir dihapus bersamaan tanpa catatan: tidak boleh keduanya lolos sehingga pengajuan Disetujui tanpa susunan. → tes di Task 4.
3. Pengaju lain menebak `/layanan/sdm/<id>` atau `/api/layanan/rundown/<id>` milik orang lain: 404, bukan data. → tes di Task 3 (query) dan Task 10 (skrip akses).
4. `rundownKey` yang dikirim klien menunjuk objek milik pengajuan lain, objek `cards/…`, atau belum diunggah: ditolak. → tes di Task 5.
5. Pengaduan tercatat Minggu 23.30 WIB masuk pekan Senin sebelumnya, bukan pekan berikutnya (pergeseran UTC). → tes di Task 2.
