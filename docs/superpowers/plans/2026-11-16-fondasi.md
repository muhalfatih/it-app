# Fondasi (Database, Login, Peran) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PostgreSQL + Drizzle (`packages/db`), login akun lokal Better Auth + otorisasi multi-peran sesuai matriks §3.3 (`packages/auth`), halaman masuk/ganti kata sandi, guard `(app)`, sidebar tersaring peran, dan halaman Setting (akun + 4 daftar).

**Architecture:** `packages/db` memegang koneksi, skema, migrasi, seed. `packages/auth` memegang Better Auth (siapa masuk) dan izin (boleh apa) — `permissionsFor(roles)` murni + guard server `requireUser` / `requirePermission`. `apps/admin` hanya route handler, halaman, aksi server, dan konfigurasi menu. Proteksi di layout server + setiap aksi server (bukan middleware/proxy).

**Tech Stack:** Next.js 16.4, React 19.3, PostgreSQL (Docker), Drizzle ORM + drizzle-kit + `postgres` (postgres-js), Better Auth (plugin `username`, `nextCookies`), zod 4, vitest, shadcn `base-maia` + `@reui`.

**Spec:** `docs/superpowers/specs/2026-11-16-fondasi-design.md`

## Global Constraints

- Patuhi `CLAUDE.md`/`AGENTS.md`: perintah dijalankan di WSL dengan nvm; komponen hanya lewat shadcn CLI `-c packages/ui` (`--dry-run` dulu, tolak timpa file yang ada); komponen domain di `packages/ui/src/components/domain/`; token tema satu-satunya sumber warna; teks UI berbahasa Indonesia.
- **Pekerjaan visual (CLAUDE.md):** sebelum menulis halaman `/masuk`, `/ganti-kata-sandi`, dan halaman Setting panggil skill `frontend-design:frontend-design`; sesudahnya jalankan `anthropic-skills:web-design-guidelines` pada hasilnya. Aturan proyek menang bila bertentangan.
- **API Better Auth & Drizzle tidak ditebak:** sebelum menulis konfigurasi, baca dokumentasi resmi (WebFetch `https://www.better-auth.com/docs/...` untuk installation, plugin username, Drizzle adapter, Next.js integration, session, database hooks; `https://orm.drizzle.team/docs/...` untuk postgres-js & drizzle-kit). Versi yang dipasang dicatat di ledger.
- Panduan Next di `node_modules/next/dist/docs` tidak bisa dibaca (izin ditolak) → hindari middleware/proxy; pakai API App Router yang stabil (route handler `app/api/.../route.ts`, server actions `"use server"`, `redirect`, `cookies()`/`headers()` dari `next/headers` — **await**-kan, keduanya async).
- Rahasia hanya di `.env` (ter-ignore); `.env.example` di-commit (tambahkan `!.env.example` ke `.gitignore`).
- **Satu `.env` di root repo.** Docker Compose membacanya otomatis; `apps/admin/next.config.ts` memuatnya dengan `process.loadEnvFile(path.resolve(<dir>, "../../.env"))` (dibungkus try/catch bila tidak ada); drizzle-kit & skrip memakai `process.loadEnvFile` / `tsx --env-file=../../.env`. Runner TypeScript untuk skrip: `tsx` (devDependency `packages/auth`).
- **Guard di setiap pintu masuk:** setiap `page.tsx` di `(app)` memanggil `requireUser()` atau `requirePermission(p)` sendiri, dan setiap aksi server dibungkus `withPermission(p, handler)` — layout bukan gerbang (aksi server melewatinya, dan layout tidak dijalankan ulang saat navigasi klien). Redirect `mustChangePassword` ada di dalam `requireUser()`.
- **Modul murni untuk logika yang dites:** `permissions.ts`, `rules.ts`, `authorize.ts` tidak mengimpor `@workspace/db` (kecuali `schema/roles` tanpa impor), `auth`, `next/*`, atau `server-only`, agar vitest tidak gagal karena env/impor.
- **Arah dependensi:** `@workspace/auth` → `@workspace/db` (tidak sebaliknya). Seed akun ada di `packages/auth`.
- Setiap aksi server: validasi input dengan zod di dalam `withPermission(...)`.
- Kata sandi: minimal 8 karakter; tidak pernah dicatat ke log/toast.
- Waktu `timestamptz`; tampilan WIB (`Asia/Jakarta`).
- Commit lokal di branch `feat/fondasi` (dibuat dari `feat/app-shell-ui`), tanpa push; aturan versioning `CLAUDE.md`; pesan diakhiri `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

export type Decision = "ok" | "unauthenticated" | "must_change_password" | "forbidden"
export function authorize(viewer: Viewer, permission?: Permission, opts?: { allowPasswordChange?: boolean }): Decision
export function withPermissionUsing<A extends unknown[], R>(getViewer: () => Promise<Viewer>, p: Permission, fn: (...a: A) => Promise<R>):

export async function setDisabled(id: string, disabled: boolean): Promise<void>      // disabled -> cabut semua sesi

// session.ts (server-only)
export type CurrentUser = { id: string; username: string; name: string; roles: Role[]; permissions: Set<Permission>;
                            bidang: ("it"|"media")[]; unitId: number | null; mustChangePassword: boolean }
export async function getCurrentUser(): Promise<CurrentUser | null>   // null bila tak ada sesi atau disabledAt terisi
export async function requireUser(opts?: { allowPasswordChange?: boolean }): Promise<CurrentUser>

export async function requirePermission(p: Permission): Promise<CurrentUser>   // forbidden -> redirect("/?akses=ditolak")
